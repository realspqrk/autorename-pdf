This is now the **recommended download**, replacing 3.2.0. **Coming from 3.x?** Read the [migration guide](https://github.com/realspqrk/autorename-pdf/blob/main/docs/migration-3-to-4.md) first: 3.x settings are not read, and [3.2.0](https://github.com/realspqrk/autorename-pdf/releases/tag/v3.2.0) stays available. It is still a beta: keep backups and [report problems](https://github.com/realspqrk/autorename-pdf/issues).

### Changed since beta 2
- **Google Drive for desktop**: files on My Drive and on shared drives are renamed now, including scans uploaded by a scanner or another device. Before, the rename was undone right away and the row said "A file with the new name already exists". Google Drive sets such a file's modified time to the moment it is renamed; the app took that as another program changing the file and put it back. The same fix covers writing document details into the PDF and Undo on those drives. A file that really changes while it is renamed is still put back, now with the message "File changed since analysis".
- **Copy and Paste**: the copy buttons (the original path in the details panel, the journal location in History) put the text on the system clipboard. Before, the toast said "Copied" but nothing could be pasted elsewhere. Paste (Ctrl+V) into text fields, such as the API key in Settings, works from other apps too.
- **Coming from beta 1:** unchanged from beta 2. A config with `company: name:` is refused with a hint; write `names: ["Your Company"]` under `company:` (or set it again in Settings).

### Known limits in this beta
- macOS: Apple silicon only; Finder Quick Actions are not tested yet. On first launch macOS asks to confirm opening an app downloaded from the internet.
- Linux: x86_64 with glibc 2.38+ (Ubuntu 24.04+, Debian 13+, current Arch). Windows 11: the right-click entries are under "Show more options".
- The window, settings and file formats may still change before 4.0.0.
